# 红嘴鸥代理服务

独立的中文代理管理页面。添加多个订阅、获取节点、排除地区、检测连通性并选择出口，通过稳定的 HTTP / SOCKS5 地址供不同应用使用。无需生图项目，也不需要额外安装订阅管理面板。

## Windows 10 开始使用

需要 Python 3.11+，或者已安装 uv。双击 `start.bat`，或在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'H:\GPTshengtu2.0\proxy-manager'
.\start.ps1
```

首次启动自动创建独立环境、安装依赖，并从 MetaCubeX 官方发布页下载 Mihomo v1.19.32，核对 GitHub 提供的 SHA-256 后安装。文件保存在本项目 `bin` 目录，不影响其他项目。

打开 **http://127.0.0.1:8787**，首次使用设置至少 10 位的管理密码，然后：

1. 在“订阅管理”添加一个或多个链接，点击“更新全部”。新增的启用订阅也会在后台定时检查时自动拉取。
2. 在“地区与筛选”勾选排除地区；也可每行填写一个排除关键词，点击保存。
3. 在“全部节点”检测候选节点，选择自动模式或手动点击“使用”。可在“管理”中修正地区、停用节点。
4. 把 `http://127.0.0.1:7891` 或 `socks5://127.0.0.1:7891` 填到其他应用的代理设置。

关闭时在启动窗口按 **Ctrl+C**，管理服务会同时停止自己启动的 Mihomo。不要运行多个实例并共用数据目录。

### 下载失败或已有内核

重新下载：

```powershell
.\.venv\Scripts\python.exe .\scripts\install_core.py
```

也可以将官方内核放到 `bin\mihomo.exe`，或用环境变量指定已有文件，然后重启管理服务：

```powershell
$env:MIHOMO_BIN = 'D:\tools\mihomo\mihomo.exe'
.\start.ps1 -SkipCoreDownload
```

内核应使用支持本项目配置的较新 Mihomo，默认已验证版本为 v1.19.32。

## 界面与动态效果

管理页面采用深色网络控制台界面。页面保留紧凑的当前出口、自动 / 手动模式、主备状态和延迟，订阅及节点列表优先展示；点击“连接详情”侧栏查看地区球体、代理入口和详细统计。

订阅页的“调整策略”打开独立侧栏，节点列表及订阅页的“选择规则”提供完整检测与切换说明。订阅的编辑、设置主订阅和删除入口位于“更多”。连接设置默认显示常用参数，检测地址、访问认证和维护操作按需展开。未保存的策略会在关闭侧栏前提示，定时刷新不会覆盖正在编辑的内容。

节点列表提供地区标识、延迟信号及当前出口高亮；订阅更新、测速、页面切换与弹窗均有状态反馈。

右上角“动效已开 / 动效已关”可以切换动态效果，并记住本机浏览器的选择。如果系统开启“减少动态效果”，页面会自动停用动画。球体离开视口或浏览器进入后台时暂停连续绘制。

球体按节点名称识别的地区显示标记，是地区示意；连接路径动效表达出口就绪状态，不表示实时流量或真实网络路径。延迟和节点数量来自实际检测结果与订阅数据。

从旧版更新后，按 **Ctrl+F5** 刷新页面。所有界面资源均由本服务提供，不依赖外部字体或动画 CDN。

## 支持的订阅

- 优先使用 Clash / Mihomo YAML，包含 `proxies` 的完整配置或纯节点列表。
- 支持常见 SS、VMess、VLESS、Trojan、Hysteria2、TUIC 原始链接或 Base64 链接列表。链接变体不保证全兼容；复杂传输或特殊协议优先选择 Mihomo YAML。
- 只导入节点；订阅中的路由、监听器和远程 provider 配置不会接管本服务。
- 同一订阅完全重复的节点会合并。不同订阅的同名节点会区分来源。地区根据名称识别，可手动修正，不等于真实出口 IP 定位。
- 单个订阅最多 8 MB / 5000 节点，最多 50 个订阅。无法识别的链接会显示提示；无有效节点的更新保留旧缓存。
- 节点配置先经过真实 Mihomo 检查。单个订阅更新失败保留其上次成功节点，其他订阅可继续更新。

## 可用性和出口

### 主订阅优先

“订阅管理”支持两种自动选路策略：

- **全部订阅择优**：默认策略，汇总所有未被排除的候选节点，按连通性和延迟选择出口。
- **主订阅优先**：在订阅的“更多 → 设为主订阅”中快捷设置，或点击“调整策略”选择策略和主订阅后保存。主订阅内按延迟择优；主订阅没有可用候选节点时，改用其他已启用订阅的节点。

主订阅只有一个，更换主订阅会更新原有标记。地区、关键词、订阅停用和单节点停用规则先执行，再判断主备；订阅下载失败时保留原缓存，缓存节点仍可用就继续使用。

主备候选节点均持续检测。主线路故障后，主订阅连续通过 **两轮检测**再回切，避免短暂恢复造成反复换出口。重复查看页面或反复读取同一份检测结果不会累计恢复轮次；第二轮成功结果需与首轮间隔约一个检测周期。默认 300 秒时，恢复确认通常还要等待下一轮检测。如果备用也不可用，而主订阅已有可用节点，会优先恢复主线路连接。

后台每 2 秒读取内核已有的健康结果并协调主备选择；这不会额外每 2 秒发起节点探测。实际探测间隔仍以“连接设置”为准。后台关闭或不运行时，主备协调无法继续工作。

出口概览显示“正在使用主订阅”“正在使用备用订阅”或恢复进度，订阅列表同时标记主订阅、备用订阅及实际使用来源。手动指定节点时保持固定，优先策略在恢复自动模式后生效。切换只影响新连接。

主订阅被停用或其节点全部被排除时使用备用；删除主订阅会恢复“全部订阅择优”，确认窗口会提前提示。设置保存在本项目数据目录，重启后保留；此前的配置默认保持“全部订阅择优”，不会自动指定主订阅。

### 自动选择状态

“全部节点”右上角会持续显示 **自动选择已开启** 或 **启用自动选择**，出口概览同时显示当前模式。选择单个节点后进入手动模式，重新启用自动选择后恢复自动选路；刷新页面会保留已保存的模式。

点击“选择规则”，可查看实际检测间隔、检测地址、故障处理方式及当前节点最近检测时间。默认 **300 秒（5 分钟）**检测一次候选节点，单次超时 **5 秒**，成功状态为 HTTP **200 / 204**；按检测延迟择优，配置 **50ms 切换容差**减少小幅波动。间隔可在“连接设置 → 自动检测间隔（秒）”调整，最低 60 秒。页面每 5 秒刷新状态不等于每 5 秒检测节点。

自动模式检测发现当前节点不可达时会重新选路；连接被拒绝或短时间多次建连失败也可能触发提前复检。不是每次失败请求都能立即换节点重试。手动模式保持指定出口，定时检测继续运行，但不会自动切换。出口变更作用于新连接，已有长连接不会自动迁移。

“检测可用”表示检测地址返回 HTTP 200 或 204，不保证某个 AI 服务接受该出口。检测结果会更新，失败节点仍留在列表便于后续恢复；自动组按实际检测结果选择。全部节点不可达时请求可能失败，不会改成直连。没有候选节点时使用 REJECT。

地区、关键词、停用订阅和停用节点共同决定候选列表。手动出口被排除或移除时切回自动选择。切换出口作用于新连接；已建立的长连接可能继续使用原出口。

多个应用使用相同入口时共享当前出口。每个应用独立出口、多入口分组以及真实出口地区检测不包含在此版本中。

## 其他机器访问

代理默认只接受本机连接。在“连接设置”开启“允许其他机器连接”，设置账号、至少 10 位密码和允许访问的 IP / 网段，保存后使用服务器实际地址。

管理页面监听地址单独设置：

```powershell
$env:PROXY_MANAGER_HOST = '0.0.0.0'
$env:PROXY_MANAGER_PORT = '8787'
.\start.ps1
```

首次设置密码应在本机完成。公网管理使用 HTTPS 反向代理和防火墙限制访问。Mihomo 控制接口仅监听本机，不对外提供。

可配置的环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PROXY_MANAGER_HOST` | `127.0.0.1` | 管理页面监听地址 |
| `PROXY_MANAGER_PORT` | `8787` | 管理页面端口 |
| `PROXY_MANAGER_CORE_PORT` | `9091` | 本机内核控制端口 |
| `PROXY_MANAGER_DATA` | 项目下 `data` | 数据目录 |
| `MIHOMO_BIN` | `bin\mihomo.exe` 或 PATH | 内核路径 |

## Docker / Linux 服务器

在项目目录运行 `docker compose up -d --build`。默认映射到服务器本机的 8787、7891 端口，数据保存在独立卷中。Mihomo 和 Python 服务在同一容器中运行。

**Docker 端口映射需要容器内代理监听 0.0.0.0。** 首次登录后在“连接设置”开启其他机器连接，填写代理账号、密码及允许网段；Docker NAT 后的来源地址可能是网桥网段，请按实际网络设置允许列表。主机映射仍保持 `127.0.0.1:7891:7891` 时只有服务器本机可以连接。其他容器访问时可加入同一 Docker 网络，使用服务名与端口，允许对应容器网段。

在 UI 修改代理端口后，需同步修改 Compose 的端口映射并重建容器。管理页面反向代理到 8787；不要把 9091 控制端口发布到公网。

## 数据与维护

- 订阅、节点缓存、筛选与密码哈希：`data\state.json`。
- 内核配置和本地排错日志：`data\core`。这些文件包含私人节点信息，备份时妥善保管，不要公开。
- 管理密码使用 PBKDF2 哈希；登录凭据使用 HttpOnly Cookie，12 小时过期，重启后需重新登录。
- 活动记录显示本次启动的最近 200 条事件，不包含订阅 URL 或节点密码。详细内核日志仅在本地文件保留。
- 更新内核前停止管理服务，运行安装脚本，再启动。安装脚本可传 `--version v1.19.32` 或 `--version latest`。
- 需要重置管理密码时，先停止服务，备份 `data\state.json`，将其中的 `password_hash` 改为 `null`，然后在本机重启并设置新密码。
