# 主订阅优先

## 规则

1. 先执行已启用订阅、地区、关键词和单节点停用筛选。
2. 默认全部订阅择优；设置主订阅后，仅在主订阅内择优，主订阅没有可用节点时才使用备用。
3. 主备持续探测；故障后的主订阅需取得间隔约一个检测周期的两轮成功结果后回切。同一份健康记录重复读取不增加轮次，恢复中再次不可用则重新计数。
4. 备用也不可用时，已经恢复可用的主线路可以立即接替，优先保证连接。
5. 手动节点保持固定，主备策略只作用于自动模式。无可用节点使用 REJECT，所有出口变更只作用于新连接。
6. 停用或过滤主订阅时使用备用；删除主订阅恢复全部订阅择优。

## 实现

- `proxy_manager\routing.py`：按指定检测地址的真实健康记录决定主备分支及恢复进度，递归解析实际出口节点。
- `proxy_manager\core.py`：主订阅优先使用 PRIMARY / BACKUP 两个延迟择优组，AUTO 为受管理的分支选择组；初始 REJECT，等待健康结果。
- `proxy_manager\service.py`：每 2 秒读取已有健康记录协调分支，记录实际切换事件；前端关闭不影响协调。
- `proxy_manager\store.py`：兼容旧配置，默认仍为全部订阅择优。
- `PUT /api/routing`：受登录和同源保护的策略设置接口。
- 前端：“调整策略”侧栏、订阅“更多”中的快捷设置、来源角色和运行状态。未保存的策略表单不会被周期刷新覆盖，关闭前会提示。

主备探测由 Mihomo 按配置的间隔执行；管理服务读取已有结果不会额外增加探测频率。新连接通过统一入口进入 OUTBOUND；手动选择直接到节点，自动模式进入 AUTO，再到当前主 / 备组。

## 验证

- 单元检查覆盖主线路较慢仍优先、失效切备用、两轮恢复、重复记录不累加、恢复中断、备用同时失效、地区排除、主订阅停用、嵌套出口解析及旧配置兼容。
- 真实 Mihomo 检查覆盖主订阅优先、故障切换、稳定恢复、手动覆盖、全部失效拒绝、地区排除和删除主订阅恢复全局择优。
- API 检查覆盖登录保护、无效策略、主订阅不存在或已停用、保存与取消优先。
- 浏览器检查覆盖设置、更换主订阅、保存全局策略、未保存表单保留、刷新后保留、删除主订阅提示与手机布局。
